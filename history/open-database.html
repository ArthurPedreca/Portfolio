Client records readable with the public key

A booking platform built with an AI tool looked finished. Behind the interface, anyone holding the app’s public key could read its clients, appointments and payments. October 2026.

What happened

The platform was getting ready to launch. In a Supabase app the public key ships to every visitor’s browser by design, so it is not a secret. What stands between that key and the data is the row level security policy on each table and the access rule on each storage bucket.

Here those rules were open. Four tables and every storage bucket answered to the public key alone, with no login. All five were closed before a single real user signed up.

How it went

  1. Looked from the outside

    Every table and bucket tested the way a stranger would: no password, only what any visitor’s browser already has.

  2. Found it open

    With only the public key, clients, appointments, payments and intake_forms returned every row. Every storage bucket was public.

  3. Closed it

    Each table got a role-based policy that limits rows to the business they belong to. Every bucket went private, with files served through signed links that expire.

  4. Before launch

    Every table and bucket now refuses the public key on its own. No real user’s data was ever in it.

Why

The policies were written so the app would work, not so each business’s data stayed separate. A rule like using (true) makes a table readable to anyone, and nothing looks wrong from the inside, because the interface only ever asks for what it is about to show.

It is the most common hole I find in apps built with AI tools. The screens are right, the demo is right, and the database is wide open.

The fix

supabase/policies/clients.sql+1 −1
  create policy "read clients" on clients for select
- using (true);
+ using (business_id in (select my_businesses()));

The same pattern went onto the other three tables. For files, the buckets were made private and the app now asks for a short-lived signed link when it needs to show one. The code above is simplified.
